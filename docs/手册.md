# 完整操作手册

本文是 [README](../README.md) 的展开版，面向**实际动手操作**：从零配置到日常更新，以及出问题怎么查。

> 文中所有 IP、路径均为**示例**，请替换成你自己的。
> 全程只需一台 Windows PC，不需要 NAS、不需要 root、不需要在电视上装任何东西。

---

## 0. 先搞清楚整条链路

```
① 核对版本   本地/电视上的版本  vs  APKMirror 上的最新版
                    ↓
② 下载       真实 Chrome 过 Cloudflare → 取 CDN 直链 → curl 拉文件
                    ↓
③ 安装       PC 解包 .apkm → adb install-multiple -r → 推送到电视
                    ↓
④ 校验       回读 versionName / primaryCpuAbi，确认真的装对了
```

**难点只在 ②**。①③④ 都是常规操作。

②之所以麻烦：APKMirror 挂了 Cloudflare 的机器人防护，`curl`、`wget`、无头浏览器**一律 403**。
绕过它的办法是用**真实 Chrome** 走 CDP 驱动，过掉验证码后从下载事件里取出文件的**预签名直链**，
再把直链交给 `curl` 下载（因为 Chrome 自己下载会被取消）。

## 1. 准备

### 1.1 电视侧要做到什么

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 系统 | Android TV / Google TV，**建议 Android 9+** | 设置 → 系统 → 关于 |
| **ADB 网络调试** | **必须开启** | 见 §2.1 |
| 与 PC 同网 | 同一局域网，能互相 ping 通 | `ping <电视IP>` |

> 电视上**不需要**装任何 App，也**不需要** Google Play。国行机型全部没有 Play，这正是要用本工具的原因。

### 1.2 PC 侧要做到什么

| 项 | 要求 |
|---|---|
| 系统 | Windows（其他系统未验证） |
| 浏览器 | **Google Chrome**，装在默认位置（或用 `CHROME` 环境变量指定路径） |
| Python | 3.9+（只用标准库） |
| adb | **不用预装**，脚本会自动下载官方 platform-tools |

`tv_adb.py` 找 adb 的顺序：`$ADB` → `PATH` → `./.tools/platform-tools/` → `~/.cache/bravia-adb/` → 自动下载。

### 1.3 网络要注意什么

- **内网与外网互不干扰**。即使 PC 上开着代理软件（Clash / v2ray 等），
  `192.168.x.x` 这类局域网地址通常走直连，**不影响连电视**。
- 如果抓 APKMirror 失败，先看 §5.1，**不要先去改代理配置**。

## 2. 首次配置（只做一次）

### 2.1 开启电视的 ADB 网络调试

索尼 BRAVIA 的路径（其他品牌类似）：

```
设置 → 系统 → 关于 → 连点「版本」7 次  →  开启开发者选项
设置 → 系统 → 开发者选项 → 「网络调试」/「ADB 调试」→ 开启
```

记下电视的 IP（设置 → 网络 → 网络状态）。

### 2.2 授权这台 PC

```bash
python skills/bravia-apk-update/scripts/tv_adb.py connect
```

- 电视上会弹出 **「允许 USB 调试吗？」** → 点**允许**，并勾选 **「一律允许来自这台计算机」**
- **只需授权一次**，之后永久生效
- 如果没弹框：确认电视没在息屏，再重跑一次命令

授权成功后输出形如：

```
connected to 192.168.1.20:5555
List of devices attached
192.168.1.20:5555    device product:...
--- 设备信息 ---
  ro.product.model             BRAVIA 4K VH22
  ro.build.version.release     12
  ro.product.cpu.abilist       armeabi-v7a,armeabi
```

**看到 `unauthorized` 就是还没授权**，去电视上点一下即可。

> ⚠️ 授权框属于系统安全对话框，**电视会禁止对它截屏**（截图会得到 0 字节文件）。
> 遇到截图空白，先看看电视上是不是正显示着某个系统弹窗。

### 2.3 配置电视地址

```bash
cp skills/bravia-apk-update/config.example.json skills/bravia-apk-update/config.json
```

```json
{
  "tv_addr": "192.168.1.20:5555"
}
```

优先级：`config.json` > 环境变量 `TV_ADDR` > 脚本内置默认值。

## 3. 日常更新流程

### 步骤 1 · 核对版本

**先看电视上现在是什么版本：**

```bash
python skills/bravia-apk-update/scripts/tv_adb.py verify
```

**再去 APKMirror 查最新版。** 关键：应用页里权威信息在 `### <App> variants` 段落，
每个变体下方有一行 `Latest: [版本](链接) on 日期`。
**页面顶部那张卡片的"最新版"只代表某一个变体，不能用来判断你这个架构有没有新版。**

**本地 APK 的版本号要读真实的，不要信文件名：**

```bash
python skills/apk-version-inspect/scripts/apk_info.py <某个.apk>
```

若是 `.apkm`，先解出 `base.apk`：

```bash
python -c "import zipfile;zipfile.ZipFile('x.apkm').extract('base.apk','.')"
```

> **判断新旧一律以 `versionCode` 为准**，不要比字符串。

### 步骤 2 · 下载

准备一个清单文件 `targets.json`：

```json
[
  {"name": "Netflix (Android TV)", "url": "https://www.apkmirror.com/apk/netflix-inc/netflix-android-tv/netflix-android-tv-13-2-0-release/netflix-android-tv-13-2-0-android-apk-download/"}
]
```

`url` 就是 APKMirror 下载页地址（**以 `-android-apk-download/` 结尾的那个**）。

```bash
python skills/bravia-apk-update/scripts/am_download.py targets.json ./downloads
```

脚本会：启动真实 Chrome → 过 Cloudflare 验证 → 点下载按钮 → 从浏览器事件取直链 → 交给 curl 落盘。

> 会弹出一个 Chrome 窗口，**这是正常的，不要手动关它**。
> 首次运行可能停在验证码页 10–15 秒，脚本会自动点击完成验证。

### 步骤 3 · 安装

```bash
# 先试装一个，确认成功再批量
python skills/bravia-apk-update/scripts/tv_adb.py install ./downloads/xxx.apkm

# 批量
python skills/bravia-apk-update/scripts/tv_adb.py install ./downloads/*.apkm
```

成功会输出：

```
=== xxx.apkm
    分片 3 个: base.apk, split_config.armeabi_v7a.apk, split_config.xhdpi.apk
    安装: ✅ Success
    回读: 16.18.0 → 16.21.0   primaryCpuAbi=armeabi-v7a
```

**`✅ Success` + 版本号确实变了，才算成功。**

可选 `--slim`：剔除 `arm64_v8a` / `x86` 等无关架构分片（32 位电视上用不到），能少装几十 MB。

可选 `--dry-run`：只打印将要执行的命令，不真的装。

### 步骤 4 · 校验

```bash
python skills/bravia-apk-update/scripts/tv_adb.py verify
```

确认两件事：
1. `versionName` 变成了新版
2. `primaryCpuAbi` 是设备支持的架构（32 位设备应为 `armeabi-v7a`）

第 2 条才说明**系统启用的确实是能跑的那个分片**，不是"装上了但起不来"。

### 回滚

```bash
python skills/bravia-apk-update/scripts/tv_adb.py downgrade ./old/xxx.apkm
```

`downgrade` 会自动加 `-d`；不加会报 `INSTALL_FAILED_VERSION_DOWNGRADE`。

## 5. 排障

### 5.1 抓不到 APKMirror

**症状**：`curl` 返回 403、页面标题是 `Just a moment...` 或 `Attention Required`。

| 排查 | 结论 |
|---|---|
| 用 `curl` 直接访问 | ❌ 必失败，别浪费时间 |
| 用 `--headless=new` | ❌ 会被判定为机器人 |
| 用无头 + 完整浏览器指纹头 | ❌ 仍然失败 |
| 把 `cf_clearance` 导出给 curl 复用 | ❌ 失败，它绑定 TLS 指纹 |
| **非无头真实 Chrome + CDP** | ✅ 可行 |

**两个必须注意的点：**

1. **不要加 `--disable-blink-features=AutomationControlled`**
   Chrome 会弹出「您使用的是不受支持的命令行标记」横幅，等于自曝自动化。
   正确做法是用 `Page.addScriptToEvaluateOnNewDocument` 注入脚本抹掉 `navigator.webdriver`。

2. **验证码的勾选框在一个闭合的 shadow root 里**，
   页面上 `document.querySelectorAll('iframe')` 返回**空数组**（整页可能只有 47 个元素、0 个 iframe）。
   纯 JS 永远点不到，必须走 CDP 的 DOM 域：

   ```
   DOM.getDocument({depth: -1, pierce: true})   # pierce 能穿透 shadow root
     → 递归找 nodeName == 'iframe'
     → DOM.getContentQuads 取 viewport 矩形
     → 在 (x + 25, y + h/2) 派发真实鼠标事件
   ```

**另一个坑：不要让 Chrome 自己下载。**
点开下载按钮后，Chrome 收到约 8–17 KB 就会 `state=canceled`，文件不落盘（换 profile 也一样，**不要去修它**）。
正确做法是从 CDP 的 `Browser.downloadWillBegin` 事件里取出 **R2 预签名直链**，交给 `curl`：

```bash
curl -sSL -o <输出文件> "https://<hash>.r2.cloudflarestorage.com/downloadprod/...(直链)"
```

> 已实测：自动下载与人工在浏览器里下载的**同一文件，MD5 / SHA-256 完全一致**。
> 预签名 URL 有时效，拿到后要立刻下载。

**只想读页面、不想下载时**，可以用文本代理通道：

```bash
curl -s "https://r.jina.ai/<APKMirror页面的URL>"
```

免费无 key 有速率限制，**间隔 7 秒比较稳**；被限时返回 `Just a moment...` 且正文只有几百字节，等 60–75 秒再试。

### 5.2 装不上

| 报错 | 原因 | 处理 |
|---|---|---|
| `INSTALL_FAILED_NO_MATCHING_ABIS` | 装的是别的架构 | 换含 `armeabi-v7a` 的变体 |
| `INSTALL_FAILED_ALREADY_EXISTS` | 没加 `-r` | `install` 子命令默认已带 |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | 装的是低版本 | 用 `downgrade` 子命令（自带 `-d`） |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` / 签名冲突 | 原应用来自 Google Play，签名不同 | 需先卸载原应用；**注意会丢数据** |
| `unauthorized` | PC 未授权 | 去电视点「允许 USB 调试」 |
| `device not found` | adb server 重启后连接丢了 | 重跑命令（脚本内部会先 connect） |
| `INSTALL_FAILED_INSUFFICIENT_STORAGE` | 电视空间不足 | 清理或换 `--slim` |
| `INSTALL_FAILED_MISSING_SPLIT` | 分片不全 | 别用 `--slim`，或确认包里 split 完整 |

### 5.3 装上了但应用打不开

**不要一上来就怀疑是自己更新弄坏的 —— 先做回滚对照。**

#### 第一步：回滚到上一版，看是否报同样的错

```bash
python skills/bravia-apk-update/scripts/tv_adb.py downgrade ./old/xxx.apkm
```

然后启动应用、截图：

```bash
python skills/bravia-apk-update/scripts/tv_adb.py shot before.png   # 新版
python skills/bravia-apk-update/scripts/tv_adb.py shot after.png    # 旧版
```

**比对两张截图的 MD5。**

- **相同** → 与应用版本**无关**，去查网络 / 账号
- **不同** → 才回头查是不是变体选错了

#### 第二步：确认是不是崩溃

```bash
adb shell logcat -b crash -d
```

如果**没有 FATAL**，说明不是崩溃，而是应用自己弹的错误页。

#### 第三步：按 PID 抓日志（关键，别按包名 grep）

```bash
python skills/bravia-apk-update/scripts/tv_adb.py log <包名> 20
```

> ⚠️ **按包名 grep 全量日志会误判**。实测踩过：日志里一条 `SSLHandshakeException`
> 的 PID 其实属于桌面启动器，不是目标应用。**必须按 PID 过滤。**

#### 第四步：看网络走了哪条路

```bash
# 有没有 VPN / 代理接管
adb shell "dumpsys connectivity | grep -iE 'vpn'"
#  关注 VpnTransportInfo{sessionId=...}、HttpProxy: [...] <port>、Uids: {...}

# 每条连接命中了哪条规则、走了哪个节点（如果电视上跑着 Clash Meta）
adb shell logcat -d | grep ClashMetaForAndroid
#  形如：[TCP] ... --> www.example.com:443 match RuleSet(...) using 🌐 非中国[JP-xxxxx]
```

#### 第五步：验证网络路径到底通不通

把电视上的代理端口转发到 PC，再对比测试：

```bash
python skills/bravia-apk-update/scripts/tv_adb.py forward 17890 7890
curl -x http://127.0.0.1:17890 -sS -o /dev/null -w '%{http_code}\n' <目标URL>
curl --noproxy '*'            -sS -o /dev/null -w '%{http_code}\n' <目标URL>
```

**两条路径返回的 HTTP 码一致 → 网络是通的，问题在服务端判定。**

> 电视上**没有 `curl` / `wget`**（通常只有 `nc`、`toybox`、`ping`），
> 别指望在电视 shell 里直接发 HTTP 请求。

#### 常见结论：服务端判定

网络实测通、TLS 都成功，但应用仍报错（如 Disney+ `Error Code 142` = 连不上服务器、
Paramount+ `technical difficulties`）→ 属于**服务端按出口 IP 做的地区判定**：
出口 IP 被标记，或**账号注册区与出口 IP 地区不一致**。

**处置：换一个与服务主力区一致的节点重试。**
（实测案例：Disney+ / Paramount+ 的主力区是美国，出口落在日本会触发判定失败，
换美国节点后立刻正常。）

**这类问题不要靠反复重装 APK 解决。**

## 7. 设计取舍（为什么这么做）

**为什么不用无头浏览器？**
实测同一条网络下，`curl` 和 `--headless=new` 都会被 Cloudflare 判定为机器人，
而非无头的真实 Chrome 能过。**拦的是客户端指纹，不是 IP** ——
所以换 IP、加代理都解决不了这个问题。

**为什么不直接解析下载页拿链接？**
APKMirror 的下载按钮是多跳的（`download.php?id&key` → 重定向 → 预签名直链），
且中间有动态校验。**监听浏览器真实产生的下载事件**比自己复刻跳转逻辑稳定得多。

**为什么下载要交给 curl？**
预签名直链本身就是为程序化访问设计的（普通 HTTPS + 签名参数），
而 Chrome 的下载栈在这个场景下会被取消。**分工：Chrome 只负责过验证，curl 负责拿文件。**

**为什么校验要看 `primaryCpuAbi`？**
双架构包在 32 位设备上是能装的，但只有 `primaryCpuAbi` 会告诉你**系统实际启用了哪个 ABI**。
不看这个，"装上了"和"能跑起来"是两回事。

**为什么建议把「检测」和「安装」分开？**
本流程依赖 APKMirror 的页面结构和 Cloudflare 策略，属于这类工具的固有脆弱性。
检测可以全自动，安装前保留一次人工确认 —— 万一哪天检测失效，你能立刻发现，
而不是某天突然发现电视上的应用莫名其妙变旧了。
